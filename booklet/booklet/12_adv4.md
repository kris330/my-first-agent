这在有依赖关系的时候是对的——没有研究报告，Writer 没法写；没有初稿，Editor 没法改。

但不是所有任务都有依赖。

## 什么时候可以并行

想象这个场景：你让三个 Agent 分析同一篇文章，各自负责一个角度：
- **事实核查员**：检查文章里有没有存疑的说法
- **风格分析师**：分析写作语气和目标读者
- **行动顾问**：给读者提出具体建议

这三件事彼此独立，谁先做完不影响另外两个。

串行跑：假设每个 Agent 需要2秒，三个加起来就是6秒。

并行跑：三个同时开始，等最慢的那个跑完就行，总共约2秒。

**加速3倍，Agent 越多收益越大。**

---

## 一个判断方法

把任务画成有向图。

有箭头（A 的结果要传给 B）的，必须串行。没有箭头相连的，可以并行。

```
串行（有依赖）：
  Researcher → Writer → Editor

并行（无依赖）：
  fact_checker  ─┐
  tone_analyst   ├→ 汇总
  action_advisor─┘
```

## 代码：ThreadPoolExecutor

Python 标准库里的 `concurrent.futures.ThreadPoolExecutor` 是实现并行最简单的方式：

```python
# multi_agent/adv4_parallel.py

from concurrent.futures import ThreadPoolExecutor, as_completed

def run_parallel(article: str, workers: list[AnalysisWorker]) \
        -> tuple[list[TaskResult], float]:
    start = time.time()
    results: list[TaskResult] = []

    with ThreadPoolExecutor(max_workers=len(workers)) as executor:
        # 同时提交所有任务
        futures = {
            executor.submit(
                w.run,
                Task(task_id=str(uuid.uuid4()), agent_name=w.name, instruction=article)
            ): w.name
            for w in workers
        }
        # 哪个先完成就先处理哪个
        for future in as_completed(futures):
            result = future.result()
            results.append(result)
            print(f"  [并行] {result.agent_name} 完成 ({result.duration_ms}ms)")

    return results, time.time() - start
```

几个关键点：

1. `executor.submit()` 提交任务，立刻返回，不等结果
2. 所有 `submit()` 调用完之后，多个 Worker 就在后台同时跑了
3. `as_completed(futures)` 不按提交顺序，而是按**完成顺序**返回——谁先跑完先处理谁

对比串行版本：

```python
def run_serial(article: str, workers: list[AnalysisWorker]) \
        -> tuple[list[TaskResult], float]:
    start = time.time()
    results = []
    for w in workers:
        task = Task(task_id=str(uuid.uuid4()), agent_name=w.name, instruction=article)
        result = w.run(task)           # 等这个跑完才继续下一个
        results.append(result)
        print(f"  [串行] {w.name} 完成 ({result.duration_ms}ms)")
    return results, time.time() - start
```

串行版本：一行 `w.run(task)` 会一直等到 Worker 返回结果才继续。并行版本：`executor.submit()` 提交之后立刻去提交下一个，不等待。

## 并行之后：汇总结果

多个 Agent 同时产出结果，需要合并。最常见的两种方式：

**方式一：直接拼接**（结果相互独立时）

```python
report = "\n\n".join(
    f"【{r.agent_name}】\n{r.output}"
    for r in results
    if r.status == TaskStatus.DONE
)
```

**方式二：用 Synthesizer Agent 综合**（需要融合判断时）

```python
def synthesize(article: str, results: list[TaskResult]) -> str:
    analyses = "\n\n".join(
        f"【{r.agent_name}】\n{r.output}"
        for r in results if r.status == TaskStatus.DONE
    )
    messages = [
        system("你是报告整合者，将多份分析整合为一段连贯的综合评估，不超过100字。"),
        user(f"原文（节选）：{article[:150]}...\n\n各方分析：\n{analyses}"),
    ]
    return chat(messages, temperature=0.4)
```

今天的演示用的是 Synthesizer——三份独立分析，最后交给一个 Agent 综合成一段话。

## 线程安全

有人会担心：多个 Worker 同时调用同一个 `OpenAI` 客户端，会不会冲突？

不会。`openai.OpenAI` 对象是线程安全的，多个线程共享同一个客户端没问题。

需要注意的是：如果你的 Worker 除了调用 LLM，还操作了**共享的可变状态**（同一个文件、同一个数据库、同一个列表），就要加锁。

今天的例子里，每个 Worker 只调用 LLM，返回字符串，没有共享状态，所以直接并行没问题。

## 何时串行，何时并行

| 场景 | 选择 |
|---|---|
| 下一步依赖上一步的输出 | 串行 |
| 多个任务彼此独立 | 并行 |
| 需要对比多个版本 | 并行 → Synthesizer |
| 不确定时 | 先串行，有性能问题再改并行 |

并行带来速度，但也带来复杂度——出了问题，多个线程的日志交叉在一起，调试更麻烦。所以"先串行，需要时再并行"是合理的策略。

## 今天的要点

1. 没有依赖关系的任务，可以并行执行
2. `ThreadPoolExecutor` 是 Python 标准库里最简单的并行方案
3. `as_completed()` 按完成顺序返回，不是提交顺序
4. 并行结果可以直接拼接，也可以交给 Synthesizer Agent 综合
5. `openai.OpenAI` 线程安全，可以多个线程共享
