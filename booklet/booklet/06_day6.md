昨天的 ReAct 是"边做边想"——每一步决定下一步，不提前计划。

这样有个问题：对于**结构清晰的任务**，ReAct 有点浪费。

比如：

> 帮我写一份关于 AI 编程工具的调研报告

这个任务，聪明人做之前都会先想：
- 第一步，搜索主流工具有哪些
- 第二步，搜索各工具的评价对比
- 第三步，整合信息，写报告

**先有计划，再按计划执行。**这就是今天要实现的 Plan-and-Execute 模式。

---

## Plan-and-Execute 和 ReAct 的区别

| | ReAct | Plan-and-Execute |
|---|---|---|
| 决策方式 | 每步实时决定 | 先整体规划，再逐步执行 |
| 适合场景 | 不确定性高，需要灵活应对 | 结构清晰，步骤可预见 |
| 用户参与 | 全自动 | 可以让用户确认计划再执行 |
| 代码复杂度 | 中 | 稍高，但结构更清晰 |

两种模式不是谁好谁坏，是不同工具适合不同场景。

## 第一步：Planner（任务规划器）

```python
# planner.py
import json
import re
from llm import chat

PLANNER_PROMPT = """你是一个任务规划专家。

用户给你一个复杂任务，把它分解成 3-6 个清晰、可执行的步骤。

可用工具：web_search（搜索）、get_weather（天气）、calculate（计算）、get_current_time（时间）

要求：
- 每步要具体，能直接执行
- 需要工具的步骤标明工具名，不需要的填 null
- 步骤数控制在 3-6 步，不要过多

只返回 JSON，不要加任何其他文字：
{
  "goal": "任务总目标一句话描述",
  "steps": [
    {"step": 1, "description": "具体步骤描述", "tool": "工具名或null"},
    {"step": 2, "description": "具体步骤描述", "tool": "工具名或null"}
  ]
}"""


def make_plan(task: str) -> dict:
    """为任务生成执行计划。"""
    response = chat([
        {"role": "system", "content": PLANNER_PROMPT},
        {"role": "user",   "content": f"请为这个任务制定执行计划：{task}"},
    ])

    try:
        return json.loads(response)
    except json.JSONDecodeError:
        match = re.search(r'\{.*\}', response, re.DOTALL)
        if match:
            try:
                return json.loads(match.group())
            except json.JSONDecodeError:
                pass

    # 解析失败，包装成单步计划
    return {
        "goal": task,
        "steps": [{"step": 1, "description": task, "tool": None}],
    }


def print_plan(plan: dict) -> None:
    """给用户看的计划展示。"""
    print(f"\n目标：{plan.get('goal', '未知')}")
    steps = plan.get("steps", [])
    print(f"共 {len(steps)} 步：")
    for s in steps:
        tool_hint = f"  （工具：{s['tool']}）" if s.get("tool") else ""
        print(f"  步骤 {s['step']}：{s['description']}{tool_hint}")
```

## 第二步：Executor（计划执行器）

```python
# executor.py
import json
import re
from llm import chat
from tool_registry import execute_tool


def _infer_params(tool_name: str, step_desc: str, goal: str) -> dict:
    """让 AI 根据步骤描述推断工具参数。"""
    prompt = (
        f"任务总目标：{goal}\n"
        f"当前步骤：{step_desc}\n"
        f"需要调用工具：{tool_name}\n\n"
        f"请生成调用该工具所需的参数，只返回 JSON 对象。\n"
        f"例如：{{\"query\": \"搜索关键词\"}}"
    )
    response = chat([{"role": "user", "content": prompt}])
    try:
        return json.loads(response)
    except json.JSONDecodeError:
        match = re.search(r'\{.*\}', response, re.DOTALL)
        if match:
            try:
                return json.loads(match.group())
            except json.JSONDecodeError:
                pass
    return {}


def execute_plan(plan: dict) -> str:
    """按计划逐步执行，最终汇总成完整答案。"""
    goal  = plan.get("goal", "未知任务")
    steps = plan.get("steps", [])

    print(f"\n开始执行计划：{goal}")
    results: list[str] = []

    for s in steps:
        step_num  = s["step"]
        desc      = s["description"]
        tool_name = s.get("tool")

        print(f"\n{'─'*40}")
        print(f"步骤 {step_num}：{desc}")

        if tool_name:
            params = _infer_params(tool_name, desc, goal)
            print(f"[调用工具 {tool_name}]，参数：{params}")
            result  = execute_tool(tool_name, params)
            preview = result[:200] + "..." if len(result) > 200 else result
            print(f"[结果]: {preview}")
        else:
            # 不需要工具，让 AI 直接处理这一步
            result = chat([{
                "role": "user",
                "content": f"请完成这个步骤：{desc}\n（这是任务「{goal}」的一部分）",
            }])
            print(f"[AI 完成]: {result[:200]}...")

        results.append(f"步骤{step_num}（{desc}）：\n{result}")

    # 整合所有步骤结果
    print(f"\n{'─'*40}")
    print("[整合结果，生成最终答案...]")

    summary = chat([{
        "role": "user",
        "content": (
            f"你完成了任务：{goal}\n\n"
            f"以下是每个步骤的执行结果：\n"
            f"{'='*20}\n"
            + "\n".join(results) +
            f"\n{'='*20}\n\n"
            f"请基于以上信息，给出完整、清晰、结构化的最终答案。"
        ),
    }])
    return summary
```

## 用户确认环节的设计意图

注意我们加了"确认执行？(y/n)"这一步。

这不是没用的设计，而是一个很重要的用户体验决策：

**让人类在 AI 大规模行动前看一眼计划。**

AI 生成的计划可能有问题——步骤太多、方向偏了、重复了。给用户一次确认机会，可以：
- 发现计划问题，取消再重新描述任务
- 了解 Agent 打算怎么做，有心理预期

这在真实产品里叫 **Human-in-the-loop**，是负责任 AI 系统的重要特征。

---

## 什么时候用 ReAct，什么时候用 Plan-and-Execute

**用 ReAct 的场景：**
- 问题是开放的，不确定需要几步
- 每一步的结果会影响下一步的决策
- 对话式交互（你来一句，我来一句）

**用 Plan-and-Execute 的场景：**
- 任务结构清晰，步骤可以提前规划
- 需要让用户确认执行计划
- 研究、报告、调研类任务

实际项目里，两种模式可以都有，用户自己选。

## 小结

今天两件事：

1. **Planner**：把任务分解成3-6步
2. **Executor**：按步骤执行，最后整合

核心思路是：先全局规划，再局部执行，最后汇总。

这个模式在更复杂的 Multi-Agent 系统里也用得到：一个规划 Agent，多个执行 Agent，分工协作。
