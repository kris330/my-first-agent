## 策略一：重试装饰器（指数退避）

网络超时和 API 限流是最常见的**临时性错误**——等一会儿再试往往就能成功。

"等一会儿再试"的标准做法叫**指数退避**：每次失败后等待时间加倍，避免短时间内密集重试反而加剧限流。

```python
# multi_agent/adv5_error_handling.py

def retry(max_attempts: int = 3, base_delay: float = 1.0,
          exceptions: tuple = (Exception,)):
    def decorator(fn):
        @wraps(fn)
        def wrapper(*args, **kwargs):
            last_error = None
            for attempt in range(1, max_attempts + 1):
                try:
                    return fn(*args, **kwargs)
                except exceptions as e:
                    last_error = e
                    if attempt < max_attempts:
                        delay = base_delay * (2 ** (attempt - 1))
                        print(f"  [重试] 第{attempt}次失败：{e}，等 {delay:.1f}s 后重试...")
                        time.sleep(delay)
                    else:
                        print(f"  [重试] 已达最大次数（{max_attempts}次），放弃。")
            raise last_error
        return wrapper
    return decorator
```

等待时间的规律是：1s → 2s → 4s → 8s……

用法很简单，加一行装饰器：

```python
@retry(max_attempts=3, base_delay=0.3, exceptions=(ConnectionError,))
def call_with_retry(prompt: str) -> str:
    return some_api_call(prompt)
```

**重要提醒：** `exceptions` 参数要具体写出要捕获的错误类型（`ConnectionError`、`TimeoutError`），**不要直接写 `Exception`**。

原因：`KeyError`、`AttributeError` 这类错误是你代码本身的 bug，重试不会解决，反而会把问题藏起来。只有临时性的外部错误才应该重试。

## 策略二：JSON 安全提取 + 降级

你让 LLM 输出 JSON，它可能给你这样的东西：

```
当然，以下是分析结果：

```json
{"name": "李华", "age": 30}
```

希望对您有帮助！
```

直接 `json.loads(raw)` 会崩溃。你需要一个安全的提取层：

```python
def extract_json_safely(text: str, fallback: dict) -> dict:
    """
    从 LLM 输出中安全提取 JSON。
    失败时返回 fallback，绝不崩溃。
    """
    # 依次尝试几种常见格式
    for marker_start, marker_end in [("```json", "```"), ("```", "```"), ("{", None)]:
        try:
            if marker_end:
                s = text.index(marker_start) + len(marker_start)
                e = text.index(marker_end, s)
                return json.loads(text[s:e].strip())
            else:
                s = text.index(marker_start)
                e = text.rindex("}") + 1
                return json.loads(text[s:e])
        except (ValueError, json.JSONDecodeError):
            continue
    print(f"  [降级] JSON 解析失败，使用默认值")
    return fallback
```

用法：

```python
raw = chat(messages)
result = extract_json_safely(raw, fallback={"name": "未知", "age": 0})
# result 一定是个合法的 dict，不会崩溃
```

**降级的核心思想：与其崩溃，不如用一个不完美但合理的默认值继续运行。**

## 策略三：流水线局部失败容忍

多 Agent 流水线里，某一步失败，不一定要让整个任务失败。

把每一步都包上重试和 fallback：

```python
class ResilientPipeline:
    def _run_step(self, step_name: str, messages: list,
                  fallback: str, max_retries: int = 2) -> str:
        """执行单个步骤，失败时重试，最终失败时返回 fallback。"""
        for attempt in range(1, max_retries + 1):
            try:
                result = chat(messages, temperature=0.5)
                if result.strip():      # 非空才算成功
                    return result
            except Exception as e:
                print(f"  [{step_name}] 第{attempt}次失败：{e}")
                if attempt < max_retries:
                    time.sleep(0.3)
        print(f"  [{step_name}] 所有重试失败，使用降级内容")
        return fallback

    def run(self, topic: str) -> dict:
        # 标题生成失败时用默认标题，不停止整个流程
        title = self._run_step(
            "标题生成",
            [system("为文章起一个吸引眼球的标题，只输出标题。"),
             user(f"主题：{topic}")],
            fallback=f"关于{topic}的思考",
        )

        # 摘要生成失败时用占位文字
        summary = self._run_step(
            "摘要生成",
            [system("用一句话概括主题，不超过30字。"),
             user(topic)],
            fallback="（摘要生成失败，请稍后查看）",
        )

        return {"title": title, "summary": summary}
```

每一步有自己的重试和 fallback，一步失败不影响后续步骤。

用户拿到的可能是"不完美的结果"，但不会是"程序崩溃"——这在生产环境里通常是更好的选择。

## 三种错误的应对原则

| 错误类型 | 原因 | 应对方式 |
|---|---|---|
| 网络超时 / API 限流 | 临时性 | 重试 + 指数退避 |
| LLM 输出格式不对 | LLM 不稳定 | 安全提取 + 降级 |
| 代码 bug（KeyError 等） | 编程错误 | **不要重试**，立刻暴露 |

最后一条是最容易犯的错误：用 `except Exception` 捕获所有错误，然后重试。结果是把编程 bug 藏了起来，系统默默地用错误的数据继续跑，产生更难排查的问题。
