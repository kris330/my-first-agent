## 配置管理：`config.py`

前6天我们用的是直接 `load_dotenv()`。

正式项目里，要做**启动检查**：缺少配置就提前报错，而不是等到运行一半才崩溃。

```python
# config.py
import os
from pathlib import Path
from dotenv import load_dotenv


def load_config() -> None:
    """加载配置，检查必要项是否存在。"""
    env_path = Path(__file__).parent / ".env"
    if not env_path.exists():
        env_path = Path(__file__).parent.parent / ".env"

    load_dotenv(dotenv_path=env_path)

    if not os.environ.get("OPENAI_API_KEY"):
        raise EnvironmentError(
            "\n错误：缺少 OPENAI_API_KEY\n\n"
            "解决方法：\n"
            "  1. 复制 .env.example 为 .env\n"
            "  2. 填入你的 API Key\n"
            "  3. 重新运行\n"
        )


def get_model() -> str:
    return os.environ.get("OPENAI_MODEL", "gpt-4o-mini")


def get_base_url() -> str | None:
    return os.environ.get("OPENAI_BASE_URL") or None
```

**国内 API 适配：**

只需要在 `.env` 里加两行：

```
OPENAI_BASE_URL=https://api.deepseek.com
OPENAI_MODEL=deepseek-chat
```

其他代码一行不改。

## llm.py：支持国内 API

```python
# llm.py
import os
from openai import OpenAI
from config import get_model, get_base_url

_client: OpenAI | None = None

def _get_client() -> OpenAI:
    global _client
    if _client is None:
        kwargs: dict = {"api_key": os.environ["OPENAI_API_KEY"]}
        base_url = get_base_url()
        if base_url:
            kwargs["base_url"] = base_url
        _client = OpenAI(**kwargs)
    return _client


def chat(messages: list[dict]) -> str:
    response = _get_client().chat.completions.create(
        model=get_model(),
        messages=messages,
        temperature=0,
    )
    return response.choices[0].message.content
```

用了一个简单的单例模式（`_client`），避免每次调用 `chat()` 都创建新的 OpenAI 客户端。

## 最终 main.py

```python
# main.py
from config import load_config
from agent_loop import ReactAgent
from planner import make_plan, print_plan
from executor import execute_plan

BANNER = """
=================================================
    我的 AI Agent 系统 v1.0
=================================================
命令：
  直接输入     → 对话模式（有记忆，自动使用工具）
  /plan <任务> → 规划模式（先制定计划再执行）
  /clear       → 清除对话记忆
  /help        → 显示帮助
  /quit        → 退出
=================================================
"""

def main() -> None:
    load_config()
    print(BANNER)

    agent = ReactAgent(max_steps=5)

    while True:
        try:
            user_input = input("你：").strip()
        except (KeyboardInterrupt, EOFError):
            print("\n再见！")
            break

        if not user_input:
            continue

        if user_input.lower() in ("/quit", "quit"):
            print("再见！")
            break

        if user_input.lower() == "/clear":
            agent.clear_memory()
            print("记忆已清除，开始新对话。\n")
            continue

        if user_input.lower().startswith("/plan "):
            task = user_input[6:].strip()
            if not task:
                print("用法：/plan 你的任务描述\n")
                continue
            print("\n正在制定计划...")
            plan = make_plan(task)
            print_plan(plan)
            confirm = input("\n确认执行？(y/n)：").strip().lower()
            if confirm == "y":
                result = execute_plan(plan)
                print(f"\nAgent：{result}\n")
            else:
                print("已取消。\n")
            continue

        # 普通对话（ReAct 模式）
        result = agent.run(user_input)
        print(f"\nAgent：{result}")
        print(f"（对话记忆：{agent.memory_count()} 条）\n")

if __name__ == "__main__":
    main()
```

## 现在你真正理解了什么

7天之后，你应该能回答这些问题：

**工具调用是怎么实现的？**
→ 靠 System Prompt 里的工具描述，AI 读了描述，返回包含工具名和参数的 JSON，程序解析执行。

**Agent 怎么记住对话？**
→ 把历史消息带进每次 API 请求，AI 能"看到"之前发生的事。

**ReAct 是什么？**
→ 让 AI 在思考、行动、观察结果之间反复循环，直到任务完成或达到步骤上限。

**Plan-and-Execute 和 ReAct 的区别？**
→ ReAct 是边做边想；Plan-and-Execute 是先全局规划，再局部执行。

## 下一步：你能去哪里

**路径1：给 Agent 加更多工具**

- 读写本地文件
- 发送邮件（`smtplib`）
- 查询数据库（`sqlite3`）
- 调用任意 HTTP API

每个都是两步：写函数 → 加进注册表。

**路径2：升级记忆系统**

现在的记忆只在一次会话里有效。

进阶做法：把消息存到文件或数据库，下次启动时加载回来，实现跨会话记忆。

更进阶：向量数据库（`chromadb`、`faiss`），把记忆做成语义搜索，找相关历史，而不是只保留最近几条。

**路径3：加 Web 界面**

命令行毕竟不够直观。

用 FastAPI + 简单 HTML 做一个 Web 界面大概需要一天。或者用 `gradio` 十分钟就能有个界面。

**路径4：去看 LangChain**

现在你真正理解了 Agent 原理，去看 LangChain 会完全不一样。

你会发现 `AgentExecutor` 对应今天的 `ReactAgent`，`Tool` 对应注册表里的每一条，`ConversationBufferMemory` 对应 `ShortTermMemory`……

它帮你封装的，正是你亲手写过的东西。

**路径5：探索 Multi-Agent**

一个 Agent 做一件事，多个 Agent 分工协作——这是更进阶的方向。

比如：一个规划 Agent，多个执行 Agent（搜索 Agent、分析 Agent、写作 Agent），协作完成复杂任务。

这就是 AutoGen、CrewAI 等框架解决的问题。
